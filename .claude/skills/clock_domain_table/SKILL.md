# Clock Domain Table — 域归属表生成器

写 RTL **之前**生成域归属表：列出每个信号所属的时钟域、CDC 路径、同步器类型。
这是 spec → RTL 之间的关键断点——CLAUDE.md 设计约束明确"写 RTL 前先画域归属表：
列出每个信号所属的时钟域、CDC 路径"，但此前全靠人工记忆，无 skill 机械化。

> **痛点来源**（示例：某 ADC 项目曾发生）：多个设计问题根因是时钟域归属没
> 在 RTL 前定清楚——中断输出一度放错域、同源反相时钟被当 CDC 处理（不需要
> 2 级同步器）、控制信号一度放错域后迁回。域归属表提前画好，这些都能避免。

## 何时调用

- **写 RTL 前**（CLAUDE.md Step 3a/3b 之后、6 之前）——这是本 skill 的主战场
- 时钟结构变更（新增/删除时钟、相位关系变化）
- 新增跨域信号时更新表
- cdc_review 首次模式的输入（CDC 路径清单来源）
- sdc-manager 生成 SDC 的输入（同步/异步判定来源）

## 输入

- spec 接口定义（§2 端口列表）
- spec 时钟与复位章节（时钟域、频率、同步关系）
- spec 功能描述中涉及的内部信号（状态、使能、事件脉冲等）
- 可选：spec_parser 输出的 ports/timing JSON

## 输出

- **域归属表**（`doc/<module>_domain_table.md`）：逐信号标注时钟域、CDC、同步器
- **CDC 路径清单**：供 cdc_review / sdc-manager 消费
- **异常项标注**：放错域的风险点、待澄清项

### 表 3：时钟域关系（示例）

| 时钟域 | 频率(上限) | 同步关系 | CDC 要求 |
|:--|:--|:--|:--|
| PCLK | 200 MHz | 与 ADC_CLK 异步 | 需要 CDC |
| ADC_CLK | 60 MHz | 与 ADC_CLKn 同源反相 180° | **不需要 CDC**（同步时钟） |
| ADC_CLKn | 60 MHz | 同上 | 1 级采样即可 |

**空模板**：
| 时钟域 | 频率(上限) | 同步关系 | CDC 要求 |
|:--|:--|:--|:--|
| `<clk>` | `<freq>` | `<同步/异步关系>` | 需要/不需要 CDC |

> **关键判定规则**：
> - 同源 + 固定相位差 = **同步时钟**，跨域只需 1 级采样，**不设 false_path**
> - 不同源 / 无固定相位 = **异步时钟**，跨域需 2 级同步器 + false_path
> （示例：某 ADC 项目 ADC_CLK/ADC_CLKn 为同源反相同步域）

## 生成流程

### Step 1: 提取时钟域

从 spec §2.2 时钟接口 + project_config 时钟域表：
- 列出所有时钟：端口名、频率（实际需求上限）、来源
- 判定两两关系：同源? 固定相位? → 同步 or 异步

### Step 2: 逐端口填表 1

对每个顶层端口：
- 方向/位宽：从端口声明
- 所属域：从 spec 时钟域归属
- 驱动沿/采样沿：从 spec 时序章节（Step 3a 接口时序表的依据）
- 跨域?：端口所属域与对端（模拟/外部）域是否异步
- **sync**：跨域则按下方判定规则确定 sync 属性
- 同步器：根据 sync 属性确定同步器类型

### Step 2a: sync 属性判定规则（跨域信号必须标注）

对每个跨域信号，按以下决策树确定 sync 属性：

```
Q1: 目标域每拍都检查这个信号吗？（FSM 在 always 块里每个时钟沿都读）
  ├─ 是 → Q2
  └─ 否 → Q3

Q2: 信号是单比特吗？
  ├─ 是 → sync=yes（实时电平，2级同步）
  └─ 否（多比特）→ 多比特不能逐位2级同步
       ├─ 配合握手信号使用？ → sync=handshake（源域寄存+直读）
       ├─ 频繁变化？ → sync=fifo（异步FIFO）
       └─ 连续计数？ → sync=gray（Gray码+2级同步）

Q3: 信号写好后到被使用之间有足够稳定时间吗？
  ├─ 是（如 ADC_EN=0 时配好，采样期间不改）→ sync=no（配置类，不同步）
  │    ⚠️ 设计契约：RTL不提供硬件保护，软件必须保证采样期间不改
  └─ 否 → Q4

Q4: 信号是1拍脉冲吗？
  ├─ 是 → sync=pulse（2级同步+边沿检测）
  │    └─ 源域快于目标域？→ 需要脉冲展宽
  └─ 否（多比特状态偶尔读回）→ sync=handshake（寄存快照+同步后读）
```

**关键判断依据：**

| 判断维度 | 问题 | 判定 |
|:--|:--|:--|
| 使用频率 | 目标域每拍查？ | 是→需要同步；否→可能不同步 |
| 变化频率 | 采样期间会变？ | 不会→sync=no；会→需要同步 |
| 信号宽度 | 单比特还是多比特？ | 单比特→2级同步；多比特→握手/Gray/FIFO |
| 信号形态 | 电平还是脉冲？ | 脉冲→sync=pulse+边沿检测；电平→sync=yes |

**本项目实际推导举例：**

| 信号 | 每拍查? | 采样期间变? | 单/多比特 | 形态 | 推导 | sync |
|:--|:--:|:--:|:--:|:--|:--|:--:|
| adc_en | 是 | 不会 | 单 | 电平 | 每拍查+单比特电平 → 2级同步 | yes |
| spt0 | 否 | 不会 | 多(3bit) | 电平 | 偶尔用+采样期间不改 → 不同步 | no |
| lp_eoc | 否 | — | 单 | 脉冲 | 1拍脉冲跨域 → 同步+边沿检测 | pulse |
| eoc_idx | 否 | — | 多(5bit) | 电平 | 多比特+lp_eoc握手 → 源域寄存+直读 | handshake |
| cal_done | 是 | 模拟控制 | 单 | 电平 | 每拍查+单比特 → 2级同步 | yes |
| lp_sw_trig | 否 | — | 单 | 脉冲 | 1拍脉冲 → 传专门模块做CDC | pulse |

### Step 3: 逐内部信号填表 2

从 spec 功能描述提取关键内部信号：
- 状态寄存器、使能、事件脉冲、数据通路、配置
- 重点：**使能、状态、输出逻辑必须同属一个时钟域**（CLAUDE.md 跨域约束）
- 若一个方案需要加额外 CDC 来凑 → 域归属画错了，停下来重想（不要继续凑）
- **每个跨域内部信号也要标注 sync 属性**（同 Step 2a 判定规则）

### Step 4: 标注异常与风险

- 放错域的风险点（如输出放非驱动域、状态跨域）
- 同步 vs 异步判定有疑问的待澄清项
- 多比特跨域是否需要 FIFO/Gray/握手

### Step 5: 输出 CDC 路径清单

供 cdc_review 消费。示例（某 ADC 项目）：
```
CDC 路径清单:
1. cal_done: ADC_CLK → PCLK, 单比特电平, 2 级同步
2. cfg_*: PCLK → ADC_CLK, 多比特配置, 2 级同步(稳定后同步)
3. mctm_trig: 异步 → ADC_CLK, 单比特脉冲, 2 级同步+边沿检测
4. muxon_reg: ADC_CLKn → ADC_CLK, 单比特电平, 1 级(同步域,非CDC)
5. ch_data: ADC_CLK → PCLK, 多比特数据, 数据直读+VALID 单独同步
```
空模板：
```
CDC 路径清单:
N. <sig>: <src_clk> → <dst_clk>, <单/多比特> <电平/脉冲>, <同步器类型>
```

## 与其他 Skill 配合

```
spec_parser          → 端口 + 时序 JSON
      ↓
clock-domain-table   → 域归属表（RTL 前的 MUST 关卡）
      ↓
rtl_generator        → 按域归属表实现 RTL（CDC 同步器）
cdc_review           → 用本表的 CDC 路径清单做深查/刷新
sdc-manager          → 用本表的同步/异步判定设 clock_groups/false_path
consistency_check 4.4→ 校验 RTL 实现与域归属表一致
```

> **位置**：本 skill 在 spec（3a 接口时序表）之后、RTL（6）之前，是
> "写 RTL 前先画域归属表"的机械化落地。spec-timing-checklist memory 提供模板，
> 本 skill 提供生成流程与多端衔接。

## 何时更新

- 新增端口/信号 → 增补表行
- 时钟结构变更 → 重判同步/异步，更新表 3 + 受影响行
- 发现放错域 → 修正表 + 同步 RTL（不允许"先改 RTL 后补表"）
