`sim/unit/<module>/reports/verification_report.md`

**验证环境**: `sim/unit/agdc_<module>/modelsim/`

---

## 编写要点

1. **测试用例表格**：每个测试应包含足够信息让读者复现——配置参数、检查内容、预期行为
2. **Bug 严重程度**：严重=功能完全错误，中等=边缘情况错误，轻微=风格/可读性
3. **根因分析**：必须写技术根因，不是"改了 X 就好了"——写"为什么错了"和"为什么这样改"
4. **修改记录**：追踪所有文件的修改，类别用标签分类（Bug 修复/风格/功能/兼容性/文档）
5. **迭代更新**：每次 RTL 或 testbench 修改后重新运行仿真，更新报告（特别是 Bug 修复状态）
