# Doc Generator — 文档生成器

根据设计需求或已有设计数据，生成符合项目规范的各类文档。

## 输出格式

| 格式 | 适用场景 | 生成方式 |
|---|---|---|
| Markdown (.md) | 设计文档、README、寄存器描述 | `Write` 工具直接写入 |
| DrawIO (.drawio) | 架构框图、时序图、状态机图 | 生成 mxGraph XML 写入 .drawio 文件 |
| Excel (.xlsx/.csv) | 寄存器列表、pinout 表、参数表 | Markdown 表格或 CSV 格式 |
| Word (.docx) | 正式设计规格书 | 先生成 Markdown 再导出 |
| PDF | 交付文档 | 先导出 Markdown 再用 pandoc 转换 |

## 设计文档规范

所有生成的设计文档必须遵循以下规范：

- Markdown 编写，结构清晰，层级分明
- 寄存器表格格式与 TRM 对齐（位域/属性/复位值/描述）
- 架构图用 DrawIO 绘制，源文件随文档一起提交到 `doc/` 对应目录
- 文档中引用芯片参考手册 (TRM) 时标注章节号，引用算法时标注论文/文档链接
- 模块接口变更后同步更新相关设计文档
- **文档中避免出现参考方案的具体型号和公司名称，仅描述技术特征**

## 流程

### Step 1: 确定输出格式与内容

根据用户需求确定：
1. 文档类型（设计文档、寄存器表、架构图、接口说明）
2. 输出格式（Markdown / DrawIO / Excel / PDF）
3. 存放路径（遵循项目目录规范 `doc/spec/`、`doc/design/`、`doc/analysis/`）

### Step 2: 生成文档内容

#### Markdown 设计文档模板

```markdown
# 模块名 — 功能简述

## 1. 功能概述

- 主要功能描述
- 关键特性列表

## 2. 接口定义

### 2.1 总线接口

| 端口名 | 方向 | 位宽 | 时钟域 | 描述 |
|---|---|---|---|---|
| clk | input | 1 | clk_sys | 系统时钟 |
| rst_n | input | 1 | — | 异步复位，低有效 |

### 2.2 数据接口

| 端口名 | 方向 | 位宽 | 时钟域 | 描述 |
|---|---|---|---|---|
| data_in | input | 32 | clk_sys | 输入数据 |
| data_out | output | 32 | clk_peri | 输出数据 |

### 2.3 接口时序附录（必需）

每个接口信号必须逐行填写其时序属性。此表在进入 RTL 前需与架构师/领域专家双人评审确认。

> **自动生成**：若 spec_parser 已输出结构化 JSON（含 ports[] 与
> timing_requirements[]），本节表格骨架应由 skill 自动拼接，**不要从空白表
> 开始**——自动填入已知的信号名/方向/位宽/时钟域，未知项标注"待填写"。
> 仅让设计者补驱动沿/采样沿/脉冲宽度等时序细节。避免人工逐行抄端口易漏信号。

**示例**（来自某 ADC 项目，展示填法）：
| 信号 | 方向 | 时钟域 | 驱动沿 | 采样沿 | 脉冲宽度 | 建立/保持要求 | 备注 |
|:--|:--:|:--:|:--:|:--:|:--:|:--:|:--|
| soc | O | ADC_CLKn | posedge adc_clkn | — | 1 adc_clkn cycle | — | 模拟在 posedge adc_clk 检测上升沿 |
| eoc | I | ADC_CLK | negedge adc_clk | posedge adc_clk | 1 negedge cycle | — | 模拟驱动，DUT 采样 |
| ... | ... | ... | ... | ... | ... | ... | ... |

**空模板**（复制使用，从 spec ports[] 自动填信号名/方向/位宽）：
| 信号 | 方向 | 时钟域 | 驱动沿 | 采样沿 | 脉冲宽度 | 建立/保持要求 | 备注 |
|:--|:--:|:--:|:--:|:--:|:--:|:--:|:--|
| `<sig>` | I/O | `<clk>` | `<edge>` | `<edge>` | `<width>` | — | |

**填写说明**：
- **驱动沿**：源端在哪个时钟沿驱动此信号（posedge/negedge/电平）
- **采样沿**：接收端在哪个沿采样（输入信号填 DUT 采样沿，输出信号填接收方采样沿）
- **脉冲宽度**：脉冲信号占几个时钟周期，电平信号填"电平"
- **建立/保持要求**：如有特殊时序约束则填写，无则填"—"

#### 2.3.1 接口时序表自动生成子流程

当 spec_parser JSON 可用时，按以下步骤自动生成表骨架：

1. 从 JSON `ports[]` 提取：信号名、方向、位宽
2. 从 JSON `timing_requirements[]` 提取：时钟域、已知驱动沿/采样沿
3. 拼接表行：已知项填入，未知项填"待填写"（醒目标注）
4. 统计"待填写"数量 → 报告"N 个信号缺时序定义，需补全后方可进入 RTL"
5. 输出骨架表 + 缺失项清单

**自动生成的价值**：避免人工从 spec 端口表逐行抄到时序表漏掉信号
（示例：某项目曾发生 spec 时序表漏标新增端口）。机械化拼接
保证"端口表有时序表就有"，缺失项一目了然。与 clock-domain-table skill 衔接：
本表逐信号时序，clock-domain-table 逐信号域归属+CDC，两者互补。
```

#### DrawIO 架构图

生成符合项目规范的 DrawIO XML 格式，包含：
- 模块框图（矩形 + 端口标注）
- 数据流向箭头
- 时钟域边界标注
- 模块实例名与 RTL 代码一致

#### 寄存器表格

| 寄存器名 | 偏移 | 位域 | 属性 | 复位值 | 描述 |
|---|---|---|---|---|---|
| CTRL | 0x00 | [0] | RW | 1'b0 | 使能控制 |
| CFG | 0x04 | [7:0] | RW | 8'h00 | 配置参数 |

#### 寄存器排布规范

生成寄存器描述文档时，必须遵循以下排布规则：

##### 1. 配对合并（示例）

逻辑上成对的参数合并到同一寄存器，减少地址空间，避免配置中间态。以下为常见布局约定（按项目风格统一）：

| 成对关系 | 合并寄存器 | 位域布局（示例） |
|----------|-----------|----------------|
| 宽+高 | `XXX_SIZE` | [27:16]=h, [15:12] rsvd, [11:0]=w |
| X+Y 坐标 | `XXX_ORIGIN` | [27:16]=y, [15:12] rsvd, [11:0]=x |
| 行+列 | `XXX_GRID` | [14:8]=rows, [7] rsvd, [6:0]=cols |

布局风格在项目内统一，不存在项目级约定时以 spec 文档为准。

##### 2. 地址连续性

删除某个寄存器后，后续所有寄存器地址依次前移，保持紧凑排列，**不留空洞**。禁止将释放的地址标记为"保留（reserved）"后再在其后追加新寄存器——应直接占用空出的地址位。

修改前后对比：

| 操作 | 错误做法 | 正确做法 |
|------|---------|---------|
| 删除 0x04 的寄存器 | 0x00, ~~0x04~~, 0x08, 0x0C（留空洞） | 0x00, 0x04, 0x08（前移紧凑） |
| 新增寄存器 | 追加到末尾 0x10 | 优先填入空闲位置，或追加后重排 |

##### 3. 位域对齐

多 bit 配置项按 4/8/16 bit 边界排布，禁止跨边界字段：

- 1-bit：可放任意位置
- 2~4 bit：起始位为 4 的倍数（bit0/4/8/12/16/20/24/28）
- 5~8 bit：起始位为 8 的倍数（bit0/8/16/24）
- 9~16 bit：起始位为 16 的倍数（bit0/16）

间隙填 rsvd，读回 0。好处：软件可用 byte/halfword 掩码独立访问，仿真波形十六进制对齐。

##### 4. 命名风格

- 寄存器名：`大写前缀_功能`，如 `FRAME_SIZE`、`MESH_GRID`
- 位域信号：`cfg_功能_细节`，如 `cfg_frame_w`、`cfg_mesh_cols`
- 尺寸类后缀：`_w`/`_h`（宽高）、`_size`（合并寄存器）
- 坐标类后缀：`_x`/`_y`、`_origin`（合并寄存器）
- 网格类后缀：`_cols`/`_rows`、`_grid`（合并寄存器）

##### 5. 批注

寄存器描述中需包含以下辅助信息，帮助使用者正确理解和使用：

- **使用方法**：典型配置序列、读写顺序、常用值示例
- **使用约束**：字段间的依赖关系、对齐要求、有效范围、互斥条件
- **行业规则**：YUV 格式编码惯例（0=420/1=422/2=422I）、地址对齐惯例（base[1:0]=0）、帧尺寸 4-byte 对齐等行业通用约定

批注写在寄存器详细描述的表格之后，用加粗小标题区分。仅标注非常规信息，命名本身已表达的不再重复。

### Step 2b: spec 完备性检查（进入 RTL 前的最后关卡）

生成模板内容后，设计者必须逐条填写接口时序附录（2.3节），然后与架构师/领域专家逐行双人评审。
此步骤未完成前不得进入 RTL 设计阶段。

#### 检查清单

```
□ 每个输出信号：驱动沿 + 时钟域 + 脉冲宽度
□ 每个输入信号：采样沿 + 时钟域 + 建立/保持时间
□ 每个可配参数：有效范围 + 默认值 + 不同配置的行为差异
□ 每个异常路径：<abort> / reset / overrun 等异常场景下的行为
□ 时钟域表格：同步关系 + CDC 要求
□ 时序图：至少覆盖最关键的采样/转换路径
□ 工程配置（project_config.md）：时钟域归属与 spec 一致
```

#### 评审流程

1. 设计者逐条宣读接口时序附录中的信号时序参数
2. 架构师/领域专家确认时序参数正确（"对，模拟就是这样工作的"）
3. 设计者逐条对应工程配置中的时钟域归属
4. 架构师/领域专家确认域归属正确
5. 双方在检查清单上逐项打勾
6. 输出完整的接口时序表 + 检查清单作为 spec 文档的一部分

### Step 3: 写入文件并验证

1. 使用 `Write` 工具写入文件到对应目录
2. 确认文件格式正确、内容完整
3. 提醒用户检查关键信息准确性
