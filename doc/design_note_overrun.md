# 设计备注 — ADC 控制器

## OVERRUN 中断事件丢失

**发现时间：** 2026-07-05（RTL 二次审查）
**严重程度：** 低（信息性）
**涉及模块：** `adc_seq_fsm`（溢出检测）、`adc_int_ctrl`（中断路由）、`adc_regfile`（INT_STAT 记录）

### 描述

当多个通道同时发生数据溢出时，INT_STAT[5]（OVERRUN）只能标记"发生过溢出"，但无法区分是哪个通道溢出。OVERRUN 是单 bit 事件，DMA 请求也是单一请求线。

### 场景

考虑以下场景：
1. CH0 采样完成 → VALID=1
2. 软件尚未读取 CH_DATA0
3. CH0 第二次采样完成 → VALID 仍为 1 → 检测到溢出 → OVERRUN 中断
4. 几乎同时，CH1 也溢出 → OVERRUN 中断已置位，无法区分新增事件

如果软件在步骤 3 处理中断时，只读 CH_DATA0 清除 VALID，不知道 CH1 也溢出了，CH1 的数据已被新覆盖而丢失。

### 影响范围

- 仅当多个通道同时发生溢出时才有此问题
- 高优先级采样中断低优先级时，低优当前通道被丢弃，也会触发溢出场景
- 单通道场景不会出现此问题

### 设计时未修复的原因

- 修复方案需要 32 个 per-channel 溢出标志位（或 OSR 机制），面积/复杂度增加
- 典型的 ADC 应用场景中，软件应在 EOC 中断中及时读取数据，避免溢出
- 实际系统中，采样率远低于总线读取速率，溢出不频繁

### 建议

- 驱动软件在 OVERRUN 中断处理中遍历检查所有使能的 CH_DATA[n][31]（VALID 位），手动确认哪些通道溢出
- 或者驱动保证在 EOC 中断中及时读完数据，不依赖 OVERRUN 机制
